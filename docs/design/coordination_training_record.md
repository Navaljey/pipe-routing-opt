# 조율 신경망 학습 기록 형식 — `coord_record/1` (V3 검토 반영 초안)

**작성일:** 2026-11-24
**근거:** OPT.Dec25 (식별자가 아니라 성질과 관계) · OPT.Dec26 (학습 데이터 = OPT 탐색 기록) · OPT.Dec27 (LNS 구역 고르기) · OPT.Req4 · Req18 (시드 · 템플릿 분리) · OPT.Req7 (결정적 예산)
**상태:** `coord_record/0` 초안 (2026-11-24) → V3 검토 (GNARL `403b1a7` §41) 반영 `/1` 초안 (2026-11-25). **2026-11-24 소유자 승인으로 필드 고정** (OPT.Dec31 · Dec32 와 함께). 필드를 바꾸려면 `/2` 로 올린다.
**`/0` → `/1` 바뀐 점:** ① 정답 (라벨) 규칙을 이 형식에서 뺐다 — OPT 는 결과 원값만 남기고, 순위 규칙은 V3 가 `coord_label/<n>` 으로 계산한다 (§5) ② 기록 시드 범위를 나눴다 (§1) ③ 바로 결과에 증분 검증 결과를 넣었다 (§3.2) ④ 선택 확률 · 서포트 자리 막힘 관계 · 남은 예산 비율 · 단독 상태 · 충돌 자리 맥락 · 배관별 이력 · 맵 크기를 넣었다.

## 0. 이 문서가 정하는 것과 정하지 않는 것

| 정한다 (OPT 소관) | 정하지 않는다 (다른 곳 소관) |
|---|---|
| 기록의 틀: 무엇을, 언제, 어느 파일에 남기는지 | 배관 · 장애물 **이름 체계와 성질 (주의사항) 목록** → 섹션 4) APR - Pipe Service Naming |
| OPT 가 계산하는 **상태 특징** (길이 · 꺾임 · 서포트 무게 …) | 성질 값의 사내 수치 (class 표 등) → skeleton `pipe_spec` · 비공개 표 (D78 · D117) |
| OPT 가 계산하는 **관계 특징** (나란히 감 · 높이 차 · 장애물과의 거리 …) | 망의 구조 · 학습 방법 · 손실 함수 → V3 (신경망 ② = 조율 신경망) |
| 결과 **원값** 을 빠짐없이 남기는 것 | **정답 (라벨) 순위 규칙** → V3 (`coord_label/<n>`) · 판정 규칙 (D77) → skeleton |

성질 목록은 이 문서에서 만들지 않는다. 섹션 4) 가 내는 **성질 표를 그대로 실어 나르는 자리** (`props`) 만 둔다 (§3.1).

## 1. 언제 남기는가

- **시드 범위 (V3 합의 2026-11-24, 모두 skeleton 학습용 `30000000 ~ 39999999` · 검증용 `40000000 ~ 49999999` 안 — 계약 변경 없음):**

  | 범위 | 쓰임 | 조율 기록 |
  |---|---|---|
  | `31000000 ~ 31999999` | **조율 학습 기록** | 남긴다 (이 범위에서만) |
  | `32000000 ~ 32099999` | V3 모델 선택용 — 학습에도 OPT 튜닝에도 쓰지 않는다 | 결과만 (학습 재료 아님) |
  | `30000000 ~ 30199999` | V3 기존 사용 영역 | 남기지 않는다 |
  | `40000000 ~ 49999999` | OPT 튜닝 (기존대로, OPT.Req4) | 남기지 않는다 |
  | `20260000 ~ 20269999` · `scenarios/` · 평가용 템플릿 (D123 ⑤) | 평가 | **기록 코드가 켜지지 않는다** |

- 나누는 단위는 **시나리오** 다. 한 시나리오의 기록을 학습 · 모델 선택에 섞어 쓰지 않는다. 템플릿 (D124) 이 들어오면 모델 선택 세트에 **학습에 쓰지 않은 템플릿** 을 일부 넣는다.
- 시작할 때 시드 · 템플릿을 확인하고, 기록 범위가 아니면 기록을 끄고 로그에 한 줄 남긴다.
- **기록 실행은 판정 실행과 따로 돈다.** 기록 실행의 예산은 확장 수 (OPT.Req7) 로 잡는다 — 증분 검증 (§3.2) 처럼 기록 때문에 늘어난 계산이 벽시계를 먹어도 탐색 경로는 판정 실행과 같다 (탐색 (ε, §3.4) 을 켜지 않은 경우).
- 기록은 판정 시간에 들어가지 않게 한다: 탐색 중에는 메모리에 모으고, 관계 특징처럼 계산이 큰 항목은 **예산이 끝난 뒤** 계산해 쓴다 (skeleton anytime 의 "보고용 지표는 예산 밖" 과 같은 방식). 판정용 측정과 기록용 실행을 한 실행에서 같이 할 때는 곡선에 영향이 없음을 확인한다 (`추정:` 영향 없음 — OPT.Stage3 에서 잰다).

## 2. 어디에, 어떤 파일로

- 위치: 환경변수 `OPT_COORD_RECORD_DIR` 가 가리키는 **레포 밖 경로**. 공개 레포에 커밋하지 않는다 — 성질 값에 사내 class 표 수치가 섞일 수 있다 (D78 · OPT.Req12). 변수가 없으면 기록하지 않는다.
- 파일: 시나리오당 하나, `<시나리오 stem>.coord.jsonl` (한 줄 = 기록 하나, 줄 순서는 결정적 — §7).
- 첫 줄은 머리 기록 (`kind = "header"`), 그다음 개체 기록 (`kind = "entity"`), 그다음 결정 기록 (`kind = "yield"` · `kind = "region"`).

## 3. 기록 종류

모든 필드에는 쓰임 표시가 붙는다. 학습 쪽은 이 표시로 입력을 고른다.

| 표시 | 뜻 | 망 입력에 넣는가 |
|---|---|---|
| `id` | 식별자 (배관 이름 · 번호 · 장애물 이름, 노드 번호) | **넣지 않는다** (OPT.Dec25). 기록끼리 잇는 데만 쓴다 |
| `feat` | 성질 · 상태 · 관계 특징 | 넣는다 |
| `label` | 정답 · 결과 | 정답으로만 쓴다 |
| `meta` | 실행 조건 | 넣지 않는다 (나누기 · 거르기에만) |

### 3.0 머리 기록 (`header`, `meta`)

`schema = "coord_record/1"` · OPT 코드 커밋 · skeleton 커밋 · 서포트 표 sha256 (해시만) · 성질 표 출처와 버전 (`props_source`, 예: `"skeleton_D116"` → 나중에 `"section4/<버전>"`) · 세트 이름 · 시드 · 템플릿 id (학습용 / 검증용) · 결정적 예산 정의 (OPT.Req7) · 작업자 수 · 머신 · **맵 크기 · 격자 셀 크기 · 길이 단위** · 탐색 ε (§3.4, 끈 경우 0).

### 3.1 개체 기록 (`entity`)

시나리오의 배관 (E2 부터 다리 단위, 책임 단위 = (배관 id, 다리 id 또는 `"main"`), D134 보완 6) 과 장애물마다 하나.

| 묶음 | 필드 | 표시 | 출처 |
|---|---|---|---|
| 식별 | `ref` (기록 안 번호), `name` (line_no 또는 생성기 번호), `leg` | `id` | 시나리오 |
| 성질 | `props` — 섹션 4) 성질 표의 한 행을 **값으로 풀어서 그대로** (예: 서비스 성질 · class · 보온 · 주의사항 플래그). E1 처럼 없는 항목은 `null` | `feat` | 섹션 4) (그때까지는 skeleton D116 · D93 · D113 · D120 필드) |
| 사양 | 호칭경 · OD · r · kg/m · 중력관 여부 · 리듀서 여부 | `feat` | `pipe_spec(pipe)` 로만 (OPT.Req12). **비공개 수치 가능** → §2 위치 규칙 |
| 단자 | 두 단자 위치 · 방향 · 단자 직관 길이, 단자 사이 직선 거리 | `feat` | 시나리오 |
| 장애물 | 종류 · 속성 (supportable · penetrable · hot · electrical …) · 상자 크기 · 위치 | `feat` | 섹션 4) / skeleton |
| 단독 상태 | 단독 루트 있음 / 없음 · 단독 확장 수 · 실패 종류 (`unreachable` · `timeout`) · 단독 J · 단독 서포트 무게 | `feat` | OPT 루트 (§7.2) |

`props` 의 열 이름과 값 목록은 섹션 4) 결과를 따르며, 이 문서는 열 이름을 고정하지 않는다. 처음 보는 서비스라도 속성 값으로 풀려 있으면 망이 읽을 수 있다 — 이것이 섹션 4) 에 요청한 조건이다.

### 3.2 양보 판단 기록 (`yield`) — OPT.Dec26 ①

우선순위 탐색 (§7.4) 에서 충돌 하나를 골라 두 자식을 만들 때마다 하나.

| 묶음 | 필드 | 표시 |
|---|---|---|
| 위치 | 노드 번호 · 부모 번호 · 깊이 · 지금까지 누적 확장 수 · 벽시계 초 | `id` / `meta` |
| 예산 | **남은 예산 비율** (확장 수 기준 · 벽시계 기준 둘 다) | `feat` |
| 충돌 | 종류 (Layer 0 위반 일반, OPT.Req13 — 관 간섭 · 단자 예약 · 서포트 충돌 · D120 금지 규칙 …) · 겹친 길이 · 겹친 자리의 위치 | `feat` |
| 충돌 자리 맥락 | 두 배관 각각의 가까운 단자까지 거리 · 그 자리가 D96 강제 직관 / 첫 꺾임 구역인지 · 충돌 자리 주변 빈 부피 비율 | `feat` |
| 두 개체 | `p`, `q` 의 `ref` (개체 기록과 연결) + **지금 상태**: 경로 길이 · 꺾임 수 · 단독 루트 대비 길이 증가 · 서포트 무게 (라우터 추정) · 지금 우선순위에서 위에 있는 배관 수 · 아래에 있는 배관 수 · **이 실행에서 비킨 횟수 · 다시 깔린 횟수** | `id` + `feat` |
| 관계 | §4 의 쌍 관계 특징 (p, q) + 이 쌍의 충돌 반복 횟수 (이력 비용, OPT.Dec23) | `feat` |
| 주변 | 충돌 덩어리 (OPT.Dec17) 크기 · 덩어리 안 충돌 수 | `feat` |
| 결과 (가) p ≺ q — 바로 결과 | 길 찾음 여부 · 다시 깐 배관 수 · 확장 수 · 벽시계 초 · 라우터 비용 합 변화 · 다시 깐 뒤 남은 Layer 0 충돌 수 · 새로 생긴 충돌 수 · **증분 검증 결과: 필수 배관 통과 수 · 서포트 실패 (support 위반) 수 · J (검증기)** | `label` |
| 결과 (나) q ≺ p — 바로 결과 | 같은 항목 | `label` |
| 선택 | 탐색이 먼저 내려간 쪽 · **그 쪽을 고른 확률** (§3.4) · 고른 근거 (규칙 이름 · 비교한 값) | `meta` |
| 나중 결과 | 탐색이 내려간 갈래 (`explored`) · 그 갈래 아래에서 나온 최선 해의 D77 점수 (통과 수 · 완전 성공 · J) · 최종 최선 해가 이 갈래 아래에 있는지 | `label` |

- 두 자식은 어차피 둘 다 다시 깔기 때문에 (§7.4 ②) **바로 결과는 두 쪽 모두** 있다. **나중 결과는 내려간 쪽만** 있다 — 다른 쪽은 `null`.
- **증분 검증 (바로 결과의 필수 통과 · 서포트 실패) 은 기록 실행에서만** 계산한다. 판정 실행의 탐색은 해 후보에서만 서포트를 검사한다 (§7.3). V3 실측 (GNARL §35.5): "작은 배관이 비킨다" 규칙은 경로를 다 놓고도 통과 −4 였고 원인이 전부 서포트 자리 없음 — 길 찾음 · 남은 충돌만으로는 이 손실이 보이지 않는다.
- **선택 편향 주의 (V3):** 내려간 쪽 = 교사가 고른 쪽이다. 나중 결과를 한쪽만 쓰면 교사의 선택이 정답으로 샌다. 그래서 비교는 **같은 종류 결과끼리만** 한다 — 두 쪽 모두 나중 결과가 있을 때 (`ceiling`) 만 나중 결과로, 아니면 두 쪽 바로 결과로 (§5).
- 천장 측정 (OPT.Question24 ①) 실행에서는 작은 세트에서 두 갈래를 끝까지 풀어 두 쪽 나중 결과를 모두 채운다 (`ceiling = true`).

### 3.3 구역 기록 (`region`) — OPT.Dec26 ② · OPT.Dec27

LNS 한 번 (구역 하나 걷어내고 다시 깔기) 마다 하나.

| 묶음 | 필드 | 표시 |
|---|---|---|
| 위치 | 반복 번호 · 누적 확장 수 · 벽시계 초 · 지금 해의 점수 (완전 성공 · 필수 통과 · J · J_physical · preference) | `id` / `meta` / `feat` |
| 예산 | 남은 예산 비율 (확장 수 · 벽시계) · 지금 구역 크기 k | `feat` |
| 후보 구역들 | 이번 반복에서 ALNS 규칙들이 낸 **후보 구역 전부** (고른 것만이 아니다). 후보마다: 낸 규칙 이름 · 규칙 가중치 · 구역 범위 특징 · 구역 안 개체 `ref` 목록 · 구역 요약 특징 (§4) | `feat` (+ 규칙 이름 `meta`) |
| 고른 구역 | 후보 중 몇 번째인지 · **후보마다 뽑힐 확률** (그 반복의 룰렛 확률) | `meta` — 학습 없는 판의 선택일 뿐, 정답이 아니다 |
| 결과 | 고른 구역의: 받아들였는지 · Δ완전 성공 · Δ필수 통과 수 · ΔJ (검증기) · ΔJ_physical · Δpreference · 서포트 실패 수 · 랙 수 · 랙 무게 변화 · 다시 깐 배관 수 · 확장 수 · 벽시계 초 · 실패 이유 (못 깔음 · 충돌 남음 · 점수 나빠짐) | `label` |

- **구역 순위 학습의 주 재료는 천장 실행** (후보 전부에 결과가 있음) 이다 (V3). 일반 실행 기록은 고른 하나에만 결과가 있어, 위 뽑힐 확률로 보정해서만 쓸 수 있다.
- 순위 학습은 "같은 반복의 후보들 중 어느 것이 더 좋은가" 를 배운다. 그래서 후보 전부의 특징을 남긴다. 결과는 보통 고른 하나만 있고, 천장 측정 (OPT.Question24 ②, OPT.Dec27) 실행에서는 후보 전부를 시도해 결과를 모두 채운다 (`ceiling = true`).

### 3.4 선택 확률과 기록 실행 탐색 (ε)

- ALNS 구역 고르기는 룰렛이라 후보마다 확률이 있다 → 그대로 남긴다.
- 우선순위 탐색의 갈래 순서는 **결정적 규칙** (라우터 비용 합이 작은 쪽 먼저, §7.4 ④) 이라 확률이 1 / 0 이다. 이대로는 일반 실행 기록을 확률로 보정할 수 없다 (V3 (다) 1).
- 그래서 **기록 실행에서만** 작은 확률 ε 로 다른 쪽을 먼저 내려가게 할 수 있게 둔다 (시드 고정, 고른 확률을 기록). 판정 실행 · OPT 튜닝 실행에서는 ε = 0. **확정 (OPT.Dec31):** 기록 실행에서 ε = 0.2 (`추정:`), 난수 = (시나리오 시드, 노드 번호).

## 4. 관계 특징 (OPT 가 계산)

모두 이름 없이 숫자 · 참거짓으로만 쓴다.

**쌍 (배관 a, 배관 b)**
- 같은 서비스인가 · 같은 계통인가 (E2) · 같은 계통이면 주관 - 다리 / 다리 - 다리 관계
- 섹션 4) 쌍 규칙의 값: 서비스 쌍 분리 거리 · 위 / 아래 금지 여부 (D120 — 예: 기름 배관 / 전기 장비) — 규칙이 없으면 `null`
- 나란히 가는 길이 (수평 · 평행, 수평 간격 ±500 mm 안, D82 기준) · 그 구간의 평균 수평 간격 · 표면 높이 차
- 묶일 수 있는가 (`groupable` · `together_at`, D100) · 못 묶이는 이유 코드 (높이 차 > 50 mm · 표 범위 밖 · 간섭 …)
- 최소 이격 − (r_a + r_b)
- **서포트 자리 막힘 (양방향):** a 의 경로가 b 의 **단독** 서포트 부재 자리를 막는 개수 · 길이, 반대로 b 가 a 를 막는 개수 · 길이. skeleton `support_blockers` (D128) 가 나오면 그것으로, 그때까지는 OPT.Req13 의 비공개 함수로 계산한다. V3 실측에서 통과 +5 의 유일한 기전이다 — `groupable` (묶임 쪽) 과 다른 축이다.
- 구경 비 · 무게 (kg/m) 비 · 중력관 여부 조합

**배관 a - 장애물 o**
- 최소 거리 · a 가 o 의 위 / 아래 / 옆인지 · 같은 서포트 면을 쓰는지 · 그 성질 조합에 규칙이 걸리는지 (D120)

**구역 (LNS 후보)**
- 범위: 상자 크기 · 위치 (구조면 · 바닥 · 천장까지 거리) · 구역 안 빈 부피 비율
- 구역 안 배관 수 · 구경 분포 · 서포트 무게 합 · 꺾임 수 합 · 랙 후보 쌍 수 · 지난 반복에서 이 구역 근처를 고른 횟수와 성공률
- 구역 안 쌍 관계 특징의 요약 (평균 · 최대 · 개수)

## 5. 정답 (라벨) — 이 형식에서 정하지 않는다

- OPT 는 §3 의 **결과 원값** 만 남긴다. 순위 규칙은 V3 가 버전을 붙여 (`coord_label/<n>`) 계산한다. 규칙을 바꿔도 기록을 다시 만들 필요가 없다.
- 참고 — V3 가 제안한 `coord_label/1` (2026-11-24, GNARL §41):
  - 양보: 같은 종류 결과끼리만 비교. 두 쪽 모두 나중 결과면 D77, 아니면 바로 결과로 **필수 통과 → 서포트 실패 → 남은 Layer 0 충돌 → 라우터 비용 변화 → 확장 수**.
  - 구역: **Δ완전 성공 → Δ필수 통과 → 확장 수당 ΔJ (검증기) → ΔJ.** 차이가 아주 작은 쌍은 동점으로 버림 (`추정:` |ΔJ| < 0.1 %).
- 시간 쪽 원값은 확장 수 (결정적, OPT.Req7) 와 벽시계를 둘 다 남긴다.

## 6. 기록 양 (`추정:`)

OPT.Stage2 기준 시나리오당 충돌 결정 수는 기본 · 계단 수 개, 밀집 50 수십 개. 개체 수백, 관계 특징은 충돌 쌍 · 후보 구역 안 쌍만 계산하므로 시나리오당 수 MB 이하로 본다. OPT.Stage3 에서 잰다.

## 7. 결정성

같은 입력 · 같은 코드 · 같은 시드면 `label` 의 벽시계 값을 빼고 파일이 바이트 동일해야 한다 (OPT.Req6). 줄 순서 = 머리 → 개체 (`ref` 순) → 결정 기록 (노드 번호 · 반복 번호 순). 작업자 2 개가 만든 기록은 완료 순서가 아니라 이 순서로 합친다.
